# Declared Pass Symbol Resolves Standards
**Status:** v1
**Date:** 2026-09-25

---

## What It Is

Test template v1 item 7, the declared pass, and its third mechanical shape. A
`# seedgo: no-test-needed(<kind>) — <prose>` line names things. Every name in the prose
has to resolve: to something in the branch's `apps/`, or, on a `(stdlib)` line, to a real
standard-library name the product actually uses. A line whose names resolve nowhere is a
declared pass on nothing.

`declared_pass_contradiction` scores the first two shapes (**H1** a declared constant whose
literal the file asserts, **H2** a bare UPPER or snake_case name absent from `apps/`). This is
the WRONG SYMBOL, and it does not replace either. A bare UPPER or snake_case name is left to
H2 so one defect never gets two verdicts.

```python
# seedgo: no-test-needed(stdlib) — os.path.getsize() and os.scandir() behavior   # @backup never calls scandir
# seedgo: no-test-needed(generated) — the file tree generated by _project fixtures  # _project is the test's own helper
# seedgo: no-test-needed(constant) — dryrun mode and file size thresholds           # names nothing at all
```

---

## What counts as a name

Plain English words are not names. Five shapes are:

| shape | example |
|---|---|
| dotted | `os.path.getsize`, `json_handler.log_operation` |
| ends in `()` | `resolve()` |
| `_`-prefixed | `_project` |
| CamelCase | `MagicMock` |
| a path | `handlers/readme/`, `copy/snapshot.py`, `a/b/c` |

A single `a/b` with no trailing slash and no `.py` is prose for "a or b": 22 seedgo lines say
`production/tests` and mean exactly that. On a `(stdlib)` line a bare word that is an
importable module (`shutil`, `pathspec`) is a name too, because that line's whole claim is
"this module". A covered-elsewhere reference (`tests/test_bypass.py`) names the file that
covers it and is never judged.

## What resolves

- **A stdlib name** — its head is a stdlib module, or a name a stdlib import binds
  (`from pathlib import Path`, `from unittest.mock import patch`, in `apps/` or the test file
  itself) — resolves when the attribute chain is REAL and the product uses its last segment.
  A real stdlib call the product never makes is a declaration about somebody else's code.
  A bare `resolve()` on "pathlib's resolve()" is looked up on the stdlib modules the same
  line names.
- **On a `(stdlib)` line**, a name that is not stdlib is the finding: `pathspec` is a library.
- **Anything else** resolves when its last segment appears as a word in the branch's `apps/`
  source text — the text, not the AST, for the reason H2 records: env-var strings, dataclass
  fields and path segments are real uses the AST's names miss.
- **A path** resolves when `apps/` has that directory or module, matched as a suffix.

## A line that names nothing

It is its own finding — unless its category is itself a standard in this pack (`ruff`,
`documentation`, `cli`). Then the line points at the checker that covers it, which is the
declaration resolving, and its prose is scope rather than a symbol. The template's model file
carries exactly that line — `documentation — that the public generator functions carry
docstrings` — and the model is the floor.

This supersedes, for every other category, `declared_pass_contradiction`'s 2026-09-23 reading
that a prose-only line is a legitimate declaration. The review of @backup's tests found such
lines covering nothing (`dryrun mode and file size thresholds`: no threshold exists).

## Check first

Measured 2026-09-25 over the fleet's test files, before the rule landed.

| | |
|---|---|
| files carrying a declared pass | 40 (backup 13, seedgo 25, trigger 2) |
| files convicted | 10 — backup 9, trigger 1, seedgo 0 |
| hits | 12 |

| finding | count |
|---|---|
| names nothing at all | 7 |
| is stdlib, but the product never uses it | 2 (`os.scandir`, `mock.patch`) |
| is not a stdlib name, on a `(stdlib)` line | 2 (`pathspec`, twice) |
| names nothing in `apps/` | 1 (`_project`) |

The template's model file, `tests/test_readme_update.py`, passes.

## Why it cannot be satisfied by accident

Every finding is a name looked up in the product or the interpreter and not found there.
There is no threshold and nothing to tune.

## Scoring

Scored, per file. Every hit names the declared line, the name and what is wrong, on ONE
check.

## The cure

Name the symbol the product has, or drop the line.
